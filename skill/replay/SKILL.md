# replay — 动手之前，先回放历史

**定律：** 昂贵的不是试错，是忘记已经试过。本 skill 把「历史即模拟器」落到提示层：每次探索性尝试的前后各加一步——前回放、后入账。本 skill 只换纪律，不产生模拟器；真正的回放池是账本（replay CLI），skill 管「什么时候用、怎么用、不准伪造」。

**触发：** 任务命中任一条即启动——多方案选型且试错有成本；试错型调试（上一招失败过）；大改/迁移；同一类任务的第二次及以后。手动点名（「先回放一下」）亦启动。

**不启动（闭清单，见 [INV] 1）：** 简单任务与闭任务（事实问答、明确指令执行、小改小补）；全新领域且账本无相关原型；用户要速答。回放本身有成本，小任务回放是负资产。

## 不变量 [INV]

1. **不启动只对闭清单。** 命中即退出；拿不准 → 一句话问用户。
2. **回放表先行。** 动手前先跑 `replay board <关键词>`，交出最近似的 ≤3 条历史尝试（做法/结果/成本/死因）。账本查无 → 明说「无历史，本次为首次探索」，禁止编造历史。
3. **反事实检查。** 每个候选做法先答一句：「最接近的那次历史尝试会怎样评价它」——历史已判死刑的做法要用，必须说出本次条件有何不同。
4. **原始记录原则。** 回放引用账本原始记录与证据路径，不引用「我记得」「一般来说」式二手原则。
5. **结果必入账。** 动作完成后当场 `replay log`：原型、做法、评估器、分数、成本、结局、死因（若败）。不入账 = 本次探索白做（账本会瘦，梦不会来）。原型写通用任务类（skill-tuning、build-fix、perf-opt），禁止写项目名——项目有专用字段。
6. **历史不是预言。** 引用历史时若条件已变（版本、环境、规模），必须声明差异；把历史当预言 = 另一种编造。

## 默认策略 [DEFAULT]

- 账本位置：`REPLAY_HOME` 或 `~/.replay/ledger.jsonl`；用 `python replay.py`（或已装配的等价入口）调用。
- 评估器自动化：原型已登记打分器时（`replay evals` 可查），一律用 `replay eval --archetype <原型>` 自动跑分并入账，不准手填分数；未登记评估器又确有价值，可向用户提议 eval-set 登记（改配置先问）。没有客观评估器的任务只记 outcome，不硬造分数。
- 探索型任务入账时开树：`tree-begin --archetype <原型> --task <任务>` 开 rollout，每次尝试 `tree-add --rollout <id> --parent <父节点id>`（缺省 root，seq 自动）；有评估器时 tree-add 自动跑分。扁平 log 仍用于非探索场景。树形带分数的历史是做梦层的唯一素材——扁平记录进不了回放模拟器。
- 回放表进对话即可；任务重要时把回放表与本次结果一起存进项目 `docs/task-context/` 或 tmp 档案。
- 与经验系统的关系：回放管「上次试 X 发生了什么」；经验条目管「下次做 Y 时注意什么」。回放中反复出现的死因，按经验入库四问起草条目，用户确认后入经验库。

## 审查信号 [HEURISTIC]

- 回放表全是成功（选择性回忆，或漏记失败）；
- 原型字段写成项目名（通用性死了，跨项目回放作废）；
- 引用历史但不带证据路径（编造前兆）；
- 连续多次探索零入账（纪律断供，账本在瘦）。

## 边界

- 本 skill 不产生模拟器，只产生纪律；真正的离线策略评估需要账本肥了之后的基础设施层（做梦层），那是后续迭代。
- 没有客观评估器的领域（文案、观点、方案），账本只能记成败不能记分数，回放结论按方向性对待。
