# 做梦层（③④）建设图纸

> 触发：当 `replay gate` 或入账提示说某原型【可进化】时，按本文件建设③④层。本文件面向零上下文的执行者（人或 agent），全部机制以 Dream-RSI 论文（arXiv:2609.14858）为准；本文档与论文不一致之处，以论文为准并回来修订本文档。

## 0. 开工前置检查（三条全过才动手）

1. 目标原型 `replay gate` 显示可进化（尝试 ≥8、不同做法 ≥2、带分数 ≥4）；
2. 该原型已登记评估器（`replay evals` 可查）——没有分数就没有梦，先补评估器；
3. 用户已批准本次建设（建新工程 + 后续做梦要花 LLM 调用费，先问）。

## 1. 论文机制速记（建设依据）

Dream-RSI 的三阶段循环：

- **在线探索**：探索策略驱动固定的 coding agent 展开一棵**发现树**并落日志；评估器固定，给每个节点打分 s_v（越大越好）；
- **构建回放模拟器**：发现树转成可复用的回放世界池；
- **做梦改进策略**：离线阶段在固定历史上评估 M 个策略版本；固定的 LLM「策略开发 agent」读轨迹与分数、改写**策略代码**；选平均分最高者（候选集含现任策略，故选定者不劣于现任）后部署上线，驱动下一轮在线探索。**模型权重、评估器、执行接口全程不动，只有探索策略代码在变。**

关键定义（③④的接口契约）：

- 发现树：根 r = 初始工作区；每个非根节点有唯一主父节点，继承父节点保存的工作区与观测，记录本次「生成—评估」的产物、快照、诊断与分数；
- 可行动集 A(T) = {r} ∪ {叶子}；策略动作 = 选一个批次 C ⊆ A(T)，|C| ≤ W（W = 并行工数）；批次同时决定「往哪续探」和「并行多少」；
- 在线 rollout：策略代码在 rollout 中冻结；轮数上限 K1；空批次或到 K1 终止；树入历史池；
- 回放（离线）：历史固定；从只含根的观测子树出发，策略逐轮选批次，回放**确定性地**揭示已记录的子节点——非根节点返回其唯一已记录子节点（若有），根节点返回最早创建的未揭示子节点（开新枝）；轮数上限 K2；空批次 / 到 K2 / 全树揭示则终止。**不生成任何历史之外的结果——无外推**；
- 回放目标：V = max s_v（发现质量）− β1·N（执行成本，N = 揭示的非根节点数）+ β2·N/max(1,k)（并行奖励，k = 决策轮数）；策略得分 = 对全部历史树的 V 取平均；
- 策略开发：开发 agent 读各版本的回放轨迹与分数，识别成功决策与反复失败，改代码产下一版；M 版后取 argmax。
- 论文 5.1 的重要实测：**把历史抽象成「高层方向性指导」注入提示词，效果一致地更差**（对固定探索和 Dream-RSI 都成立）——回放具体树，不写空洞原则。

## 2. 数据层升级：账本 → 发现树

ledger.jsonl 不废，记录加字段（旧记录视为无树的扁平尝试，向后兼容）：

```json
{
  "id": "...", "rollout": "r1", "parent": "root或节点id", "seq": 3,
  "workspace": "证据/快照路径", "artifact": "产物路径",
  "score_value": 87.0, "diagnostics": "评估器原始输出摘要"
}
```

- 同一原型下，一次探索任务 = 一棵发现树（rollout id）；节点按 `seq` 定创建顺序（根节点揭示顺序要用）；
- `score_value` 为数值（评估器分数），无评估器的原型不进树；
- 新增命令：`replay tree-begin --archetype X`（开树，返回 rollout id）、`replay tree-add --rollout r1 --parent <id> ...`（挂节点，自动 eval 打分入账并挂树）。

## 3. ③ 回放模拟器（replay simulate）

新增 `replay simulate --archetype X --policy <策略文件> [--beta1 0.1 --beta2 0.05 --k2 50] [--json]`：

1. 取该原型历史池中的全部发现树；
2. 对每棵树：从只含根的观测子树开始，逐轮调用策略的 `select_batch(observed_nodes, W)`（实现见 §4），按论文规则确定性揭示子节点（非根=唯一已记录子节点；根=最早创建的未揭示子节点）；
3. 终止条件：空批次 / 达 K2 / 全树揭示；
4. 按公式算每棵树的 V（含三项分解），输出跨树平均分、逐树轨迹摘要、覆盖率（揭示节点 / 树总节点）；
5. **覆盖率为 0 的分叉不参与评分**；某候选在过半树上覆盖率为 0 → 输出「证据不足，继续攒历史」，不硬产结论。

默认参数（论文量级缩放）：W=1（本地串行起步）、K2=50、β1/β2 按原型量级标定——标定方法：先跑现任策略拿到 V 的三项量级，把 β1 设为「让成本项与质量项同量级」的值，β2 取 β1 的一半起步。标定过程写进做梦报告。

## 5. ④ 做梦循环（replay dream）

新增 `replay dream --archetype X --M 5`（宿主 agent 执行，流程如下）：

1. 评估现任策略（π0）在全部历史树上的得分 V0；
2. 循环 M 次：宿主 agent 扮演论文的「策略开发 agent」——读最近版本的轨迹与分数（成功决策 + 反复失败），改写策略代码产出 π(m+1)，`simulate` 评估得 V(m+1)；
3. 从 {π0..π(M-1)} 取 argmax——**候选集含现任，故选定者保证不劣于现任**（论文的单调性保证，本地同样成立）；
4. 产出做梦报告：各版本得分、三项分解、胜出者的行为差异说明、覆盖率声明；
5. **部署闸门：报告交给用户拍板后才改 `active.json`**——这是我们相对论文增加的人工闸门（论文自动部署），不改论文机制，只在部署点加闸；
6. 成本熔断：一次做梦的 LLM 决策调用 ≤ 20 次，超额即停并交出已有结果。

部署后的闭环：下一次在线探索用新策略（`tree-add` 的父节点选择听它的）→ 新树入池 → 历史扩大 → 下次做梦素材更多。这就是递归自我改进。

## 6. 与论文的差异（显式声明，不许静默改）

| 点 | 论文 | 本地 |
| --- | --- | --- |
| 规模 | 单任务数万次调用 | 单原型几十条起步 |
| 评估器 | 客观数值（基准分/运行时） | 可能有 LLM 软评估——其得分按方向性对待 |
| 部署 | 自动 | 用户拍板后改 active.json |
| 并行 W | 多 worker | 默认 1，保留并行奖励项以便以后升 W |
| 在线 rollout 冻结策略 | 是 | 是——一次探索中途不换策略 |

## 7. 失败与边界

- 做梦结果全候选「证据不足」→ 输出「历史不够，继续攒」，不硬产策略；
- 历史超过 90 天的树降权（条件漂移）；
- 论文 5.1 的警示是硬约束：**禁止把回放历史总结成「高层原则」注入提示词**——回放就回放具体树；这条同时是我们经验系统条目写作的边界提醒（条目要具体、带证据）。
